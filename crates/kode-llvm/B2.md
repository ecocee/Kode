# B2: runtime, strings and ownership

Stage B2 of ADR 0035 builds on the B1 crate. It adds no new emission machinery
for strings or reference counting — MIR already carries `Retain`/`Release`,
`Call` to `RtFn`, `Load`/`Store` and the error slot, and B1 emitted them — so
B2's work is proving that placement, closing the gaps the audit found, and
recording the evidence.

## What was verified

- **Strings**: static literal layout (`[rc=-1][kind=1][len][bytes]`), concat,
  length, equality, interpolation through `kode_int_to_str`/`kode_float_to_str`/
  `kode_bool_to_str` and `kode_str_concat`.
- **Reference counting**: `kode_retain` on aliasing, `kode_release` on every
  owner, including both paths of an early return and the merged exit block MIR
  produces.
- **Printing**: `kode_print_int/float/bool/str`, `kode_print_sep`,
  `kode_print_nl`, including bools widened to `i64` at the ABI boundary.
- **Errors**: `kode_err_throw`, the pending slot (`kode_err_pending`/
  `kode_err_take`), caught errors, propagation through a wrapper, and uncaught
  errors reaching stderr and exiting non-zero.
- **Optionals**: `none` is a null reference (`i64 0`), never `undef`; `??`,
  `== none` and unwrap guards behave as Cranelift's.

## Tests added (15, all in new files)

`tests/runtime_semantics.rs` (7 end-to-end, each built and run with
`KODE_LEAK_CHECK=1`): concat/length/equality, interpolation, 5,000 allocations
in a loop, optionals, caught + propagated + printed errors, 2,000 early returns
that build strings, and an uncaught error.

`tests/ir_runtime.rs` (8 shape tests): runtime calls for strings, the static
literal layout byte for byte, conversion, error slot, `none` never `undef`,
unwrap guard, aliasing retains, and releases on both return paths.

Crate total: 27 tests. Workspace: **135 tests pass** with `KODE_LEAK_CHECK=1`.

## Parity sweep

Every `tests/run-pass` program with an `.out` file was built by both backends
and run with `KODE_LEAK_CHECK=1`:

- **44 of 45**: identical stdout to Cranelift and to `.out`, empty stderr.
- 1 failure: `modules_alias.kode`, which needs `kode-cli`'s import loader.

All `examples/*.kode` that terminate were compared too: `bank`, `config`, `fib`,
`hello`, `pipeline`, `report`, `tour` are byte-identical (errors, optionals,
JSON, maps, channels and tasks included); `wordcount` matches after the fix
below; `api.kode` is a server and runs until killed; `db/postgres.kode` needs a
database.

## Measurements

macOS arm64 laptop, best of three, both built in release.

| Program | Cranelift | LLVM | Binary (Cranelift / LLVM) |
|---|---:|---:|---:|
| 100k interpolated strings + compare + len | 0.046 s | 0.047 s | 1,370,784 / 1,367,792 |
| 20k throws/catches | 0.004 s | 0.004 s | 1,373,328 / 1,370,320 |

Both lost nothing to the runtime calls: the runtime does the work in both
backends, and the IR difference is the call itself. Binary size is 3 KB
smaller, the same constant difference B1 saw.

## Fix found by the audit (the one existing-file edit)

`examples/wordcount.kode` failed to compile: `kode_exit` is both an `RtFn` and a
named standard-library function, so the IR declared it twice and clang rejected
the module. Cranelift tolerates repeated imports; LLVM does not.

`crates/kode-llvm/src/lower.rs`, `declarations()`: a `HashSet` of emitted names,
so each C symbol is declared once. That is the only edit to a file that existed
before B2, and it is inside this crate — no production file, the CLI, the
runtime, Cranelift or any test outside this crate changed.

## Unsupported at B2 (explicit)

- No MIR `Inst`, `Rvalue` or `Terminator` variant is unhandled; every one has an
  emission path. What is missing is *performance* work, not coverage:
  Cranelift's inlined list fast paths (`try_inline_list`), so list-heavy code
  calls the runtime (sieve: 0.303 s vs Cranelift 0.028 s).
- Single-file programs only: `import`, packages, `kode.toml` need the CLI loader.
- No debug info, `-g`, LTO, or cross-compilation.
- Not integrated: no `--backend` flag, Cranelift stays the production default.

## Integration requirements (unchanged from B1)

1. `crates/kode-cli/src/main.rs`: a `--backend=llvm` option and an LLVM branch in
   `object_for` that calls `kode_llvm::emit` + `kode_llvm::compile_ir`; the link
   step and embedded runtime archive stay as they are.
2. The CLI keeps ownership of imports/packages; the prototype's `front.rs` is
   then only used by tests.
3. B6/B7: flip the default, benchmark, then delete Cranelift (ADR 0035).
