# B3: collection fast paths

Stage B3 of ADR 0035. The sieve regression came from calling the runtime for
every list operation; this stage emits the same inline paths Cranelift's
`try_inline_list` does, with the same layout, bounds check and ownership.

## Implemented (all in `src/lower.rs`, this crate only)

| MIR call | Emission |
|---|---|
| `ListLen` | load `i64` at object offset 16 |
| `ListGet` | bounds check, then `data = load offset 32`, `addr = data + idx*8`, load `i64` |
| `ListGet8` | same, one byte per item, `load i8` + `zext` (packed bool lists) |
| `ListSet` (non-ref item) | bounds check, store `i64` at `data + idx*8` |
| `ListSet8` | bounds check, `store i8` |
| `ListSet` (ref item) | **runtime call**, because the old item must be released |
| `ListPush` / `ListPush8` | `len < cap` fast path (store, `len+1`), else the runtime push, joined |
| `ListSlice`, maps, JSON | runtime calls, exactly as Cranelift |

The bounds check is the same unsigned compare (`idx >= len` also catches
negatives), and an out-of-range index calls `kode_list_oob(idx, len, line)`
before `unreachable`, so the message and line number match.

### ABI bug found and fixed

The B1 table declared `kode_list_get8` with two parameters and `kode_list_set8`
with three; the runtime takes three and four. LLVM accepted the extra call
arguments silently (Cranelift would not), so those calls were passing values the
ABI did not describe. Both entries now match `kode-codegen/src/runtime.rs`.

## Measurements

macOS arm64 laptop, best of three, `--release`/`-O2`, identical inputs.

| Workload | Cranelift | LLVM before B3 | LLVM after B3 | C `-O2` |
|---|---:|---:|---:|---:|
| sieve (10M packed bool items) | 0.027 s | **0.304 s** | **0.032 s** | 0.013 s |
| fib(38) | 0.093 s | 0.059 s | 0.058 s | 0.058 s |
| loop_mod | 0.032 s | 0.015 s | 0.015 s | 0.012 s |
| mandel | 0.015 s | 0.013 s | 0.016 s | 0.012 s |
| 200k int push + read loop | 0.003 s | (runtime calls) | **0.002 s** | — |
| 20k map insert/lookup | 0.019 s | 0.019 s | 0.019 s | — |

The sieve regression is gone: 9.5x faster than the B2 build and within 19% of
Cranelift, 2.5x of C. Lists of ints are now slightly faster than Cranelift; maps
are at parity because both call the runtime. mandel moved from 0.013 to 0.016 s
between runs; it is dominated by float work and the difference is run-to-run
noise, not a code change.

Binary size: sieve 1,368,248 bytes (Cranelift 1,371,208), lists 1,368,800
(1,371,784), maps 1,459,408 (1,462,584) — about 3 KB smaller each, the same
constant delta as B1/B2.

## Tests

- `tests/collections.rs` (7, end-to-end with `KODE_LEAK_CHECK=1`): int lists
  (push/get/set/len/iterate/slice), packed bool lists, string lists through the
  ref-set runtime path, out-of-range message, maps, nested collections, JSON
  parse/index/encode.
- `tests/ir_collections.rs` (7): inline len/get (and no runtime call), packed
  byte loads, push fast/slow/join, packed push, ref-set stays in the runtime,
  slices, maps and JSON call the runtime.

Crate total **41 tests**; workspace **149 tests pass** with `KODE_LEAK_CHECK=1`.

## Parity sweep

- `tests/run-pass`: **44 of 45** byte-identical output and empty stderr under
  `KODE_LEAK_CHECK=1`; `modules_alias.kode` still needs the CLI import loader.
- `examples/*.kode`: all 9 identical (the two that need a server or a database
  were only compared as far as they run).

## Unsupported / unchanged

- No inline path for slices, maps, JSON, or `ListSet` with a reference item:
  Cranelift has none either, so behaviour matches; only call overhead differs.
- Single-file programs; no imports, packages or `kode.toml`.
- No debug info, `-g`, LTO or cross-compilation.
- Not integrated: no `--backend` flag; Cranelift is still the production
  backend. Full collection parity is *tested for the programs above*, not
  proven for every collection shape the language allows.

## Integration requirements (unchanged)

1. `crates/kode-cli/src/main.rs`: `--backend=llvm` plus an LLVM branch in
   `object_for`; linking and the runtime archive stay as they are.
2. The CLI keeps imports/packages; the prototype's `front.rs` becomes test-only.
3. B6/B7: flip the default after conformance, then delete Cranelift.

## Files touched

`src/lower.rs` (inline paths + ABI table fix), `tests/collections.rs`,
`tests/ir_collections.rs`, this file. No file outside `crates/kode-llvm`
changed; the CLI, MIR, runtime, Cranelift, docs and existing tests are untouched.
