# Cycle leak evidence (ADR 0038)

Measured: 2026-11-11, on the compiler at `feat/platform-ci`.
Machine: macOS 27.2 arm64 (Apple silicon), `kode 0.3.5`, LLVM backend.
Runner: `./benchmarks/leaks/run.sh` with `KODE_LEAK_CHECK=1`.

This file is the evidence AGENTS.md requires before a memory-model change:
the leak is real, it grows with the data, and it is invisible until the program
exits. It is not generated by `benchmarks/run.sh`, so regenerating the main
benchmark report does not touch it.

## Result

| program | shape | stdout | exit | leaked objects |
|---|---|---|---:|---:|
| `nocycle.kode` | two objects, back-edge cleared (`b.next = none`) | `a b` | 0 | 0 |
| `cycle.kode` | two objects pointing at each other with strong fields | `a b` | **3** | **2** |
| `ring.kode` | ring of 10,000 objects, each owning the next | `10000` | **3** | **10,000** |

The exit code comes from `kode_rt_finish` (`crates/kode-rt/src/lib.rs`): with
`KODE_LEAK_CHECK=1` it prints `kode: memory leak: N object(s) were never freed`
to stderr and exits 3. The leak count is the runtime's own live-object counter,
so it is exact, not an RSS estimate.

## What this shows

1. **The leak is proportional to the cycle.** Two objects leak 2; a ring leaks
   10,000. A single forgotten back-link in a tree leaks the whole graph, which
   is why "just break the cycle by hand" fails at scale.
2. **Nothing detects it at the point of the mistake.** `cycle.kode` compiles
   clean, runs, prints the right answer, and only reports at exit — under a
   flag that only `cargo test` sets. A production binary silently keeps the
   memory.
3. **The manual convention works, and is unenforced.** `nocycle.kode` is the
   same program with one line added; it exits 0. The language cannot tell the
   two apart, so the burden is entirely on the author.
4. **`weak` will not change rows 2 and 3.** After ADR 0038 is implemented these
   three programs are expected to behave exactly as they do now: `weak` removes
   the *need* for a strong back-edge, it does not collect cycles that are
   already strong. This table therefore stays as a regression guard for the
   strong path, and a fourth program (`weak_parent.kode`, once the syntax
   exists) will cover the `weak` path and must exit 0.

## Reproduce

```sh
cargo build --workspace           # the debug compiler
./benchmarks/leaks/run.sh         # prints the table and exits 0 when the state matches
```

`run.sh` fails if any number moves, so a change to the leak behaviour cannot
land without updating this file and ADR 0038 in the same commit.
